# ClinicCare

ระบบจัดการคลินิกสำหรับโครงงาน Laravel 12 และ MySQL มีหน้าล็อกอินผู้ดูแล แดชบอร์ด และหน้าจัดการผู้ป่วย แพทย์ และนัดหมาย

## เริ่มต้นใช้งานด้วย XAMPP

1. เปิด Apache และ MySQL ใน XAMPP
2. เปิด phpMyAdmin ที่ `http://localhost/phpmyadmin` แล้วสร้างฐานข้อมูลชื่อ `clinic_db` โดยเลือก Collation `utf8mb4_unicode_ci` หรือ import ไฟล์ sql
3. ตรวจสอบค่าเชื่อมต่อในไฟล์ `.env` ให้ตรงกับ MySQL ในเครื่อง:

   ```dotenv
   DB_CONNECTION=mysql
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_DATABASE=clinic_db
   DB_USERNAME=root
   DB_PASSWORD=
   ```

4. ติดตั้ง dependency และเตรียมตารางกับข้อมูลตัวอย่าง:

   ```sh
   composer install
   php artisan key:generate
   php artisan migrate --seed
   php artisan serve
   ```

5. เปิด `http://127.0.0.1:8000` แล้วเข้าสู่ระบบด้วยบัญชีสำหรับเครื่องพัฒนา:

   - อีเมล: `admin@clinic.co.th`
   - รหัสผ่านเริ่มต้น: `password`

      บัญชีแพทย์ตัวอย่างใช้ `doctor1@clinic.co.th` ถึง `doctor10@clinic.co.th` รหัสผ่าน `password` บัญชีแพทย์แต่ละบัญชีผูกกับแพทย์คนเดียว หน้า **จัดการข้อมูลแพทย์** แสดงชื่อแพทย์และอีเมลเข้าสู่ระบบคู่กัน และเปลี่ยนรหัสผ่านได้จากหน้าแก้ไขข้อมูลแพทย์ของแอดมิน

      เปลี่ยน `ADMIN_PASSWORD` และ `DOCTOR_PASSWORD` ใน `.env` ก่อนสร้างข้อมูลตัวอย่าง และอย่านำบัญชีตัวอย่างไปใช้บนเซิร์ฟเวอร์สาธารณะ

   Seeder สร้างบัญชีผู้ดูแล ผู้ป่วยตัวอย่าง 100 คน แพทย์ 10 คน บัญชีแพทย์ 10 บัญชี และนัดหมายตัวอย่าง 120 รายการ โดยกระจายจำนวนให้แตกต่างกันแต่สมดุลในช่วง 6 เดือนล่าสุด พร้อมอาการและผลประเมินตัวอย่างภาษาไทยที่สัมพันธ์กันเพื่อการสาธิต (เป็นข้อมูลสมมติ ไม่ใช่เวชระเบียนจริง) หากมีข้อความ Faker เดิม ให้เรียก `php artisan db:seed --class=AppointmentSymptomsSeeder` เพื่อปรับอาการและผลประเมินตัวอย่าง โดยคงวันนัด สถานะ และข้อมูลอื่นไว้ นัดที่ยังรอตรวจหรือยกเลิกจะไม่มีผลวินิจฉัย การเรียก `php artisan migrate:fresh --seed` จะล้างข้อมูลเดิมทั้งหมดและสร้างใหม่

## ส่วนประกอบหลัก

- `patients`: ข้อมูลผู้ป่วยและข้อมูลสุขภาพพื้นฐาน
- `doctors`: ข้อมูลแพทย์และความเชี่ยวชาญ
- `appointments`: นัดหมาย อาการ ผลวินิจฉัย และสถานะ โดยเชื่อมกับผู้ป่วยและแพทย์
- `users`: บัญชีผู้ดูแลระบบ (`is_admin`)

### บทบาทผู้ใช้งาน

- **ผู้ดูแล (Admin):** จัดการผู้ป่วย แพทย์ บัญชีแพทย์ และนัดหมายทั้งหมด
- **แพทย์ (Doctor):** เห็นเฉพาะนัดหมายที่ผูกกับบัญชีของตน เปิดดูข้อมูลผู้ป่วยในนัดหมาย และบันทึกอาการ/ผลวินิจฉัย/สถานะตรวจได้ ไม่สามารถสร้างนัดหมาย เปลี่ยนผู้ป่วยหรือแพทย์ ลบข้อมูล หรือเปิดหน้าจัดการของ Admin
- Admin สร้างบัญชีแพทย์ได้จากหน้าเพิ่ม/แก้ไขแพทย์ โดยกำหนดอีเมลและรหัสผ่านบัญชี จากนั้นแพทย์ใช้หน้า Login เดียวกัน
- ผู้ป่วยทั่วไปเปิดหน้า **ตรวจสอบสถานะนัดหมาย** จากหน้า Login ได้โดยไม่ต้องเข้าสู่ระบบ โดยยืนยันด้วยเลขบัตรประชาชนและเบอร์โทรศัพท์ที่ลงทะเบียน ระบบแสดงวันนัด แพทย์ แผนก และสถานะเท่านั้น ไม่เปิดเผยอาการหรือผลวินิจฉัย และจำกัดการค้นหา 5 ครั้งต่อนาทีต่อ IP

การจำกัดข้อมูลแพทย์ถูกตรวจในฝั่ง Controller ทุกครั้ง ไม่ได้อาศัยการซ่อนเมนูบนหน้าจอเพียงอย่างเดียว

ตารางหลักทั้งสามมีทั้งหมด 26 ฟิลด์ตามข้อกำหนดโครงงาน โดย `appointments.patient_id` และ `appointments.doctor_id` เป็น Foreign Key ที่ลบนัดหมายที่เกี่ยวข้องให้อัตโนมัติเมื่อผู้ป่วยหรือแพทย์ถูกลบ ก่อนยืนยันการลบ ระบบจะแจ้งเตือนผลดังกล่าว

แดชบอร์ดมีการ์ดสรุป ผู้ป่วยทั้งหมด นัดหมายวันนี้ และแพทย์ที่ออกตรวจวันนี้ พร้อมกราฟแท่งจำนวนนัดหมายย้อนหลัง 6 เดือน และตารางนัดหมายล่าสุดที่เปิดดูรายละเอียดหรือแก้ไขได้

## ทดสอบ

